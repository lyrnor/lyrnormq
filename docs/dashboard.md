# Dashboard

React 控制台复用页面设计，读取当前进程的真实会话、订阅、保留消息元数据、
MQTT PUBLISH/字节计数和启动配置。Broker 会话管理仍为只读；规则、连接器与
Webhook 动作通过独立写接口管理，与 MQTT 身份认证相互独立。

## 构建和运行

```sh
cd dashboard/web
npm ci
npm run build
cd ../..
cargo build --release -p rmqtt
# 创建权限受限的令牌文件；不要将它加入 Git 或输出到日志。
(umask 077; openssl rand -hex 32 > /tmp/rmqtt-admin.token)
target/release/rmqtt --listen 127.0.0.1:1883 \
  --admin-listen 127.0.0.1:8080 --admin-token-file /tmp/rmqtt-admin.token
```

打开 `http://127.0.0.1:8080/`，在登录页输入令牌文件内容。令牌只留在页面内存，
刷新后需重新输入。退出时清除页面数据。默认未设置管理 CLI 时不启用管理端口。
服务器远程访问使用 SSH 本地转发，例如 `ssh -L 8080:127.0.0.1:8080 USER@HOST`。
该 HTTP 服务仅允许 loopback 数字地址；TLS/反向代理与访问控制由部署环境配置。

React 生产构建通过 include_dir 嵌入 Rust 二进制。部署只需复制 `rmqtt`，
运行目录不需要 `dashboard/web/dist` 或 Node.js；令牌、证书、持久数据仍是各自
独立的运行配置，绝不编入二进制。管理服务仍默认关闭。

可使用一条命令完成前端与 release 构建：

```sh
./scripts/build-rmqtt.sh
# 交叉编译时仍在本机生成前端，再传递 Rust 目标参数：
./scripts/build-rmqtt.sh --target x86_64-unknown-linux-musl
```

脚本透传 Cargo 参数；交叉编译需另外安装对应 Rust target 和链接工具链。
Cargo 的 build.rs 不自动安装依赖或调用 npm，缺少或不合法的 dist 会明确失败。
前端源码变化后必须重新执行前端构建，再重编 Rust；dist 文件变化触发 Cargo
重新嵌入，不需要 cargo clean。

`--dashboard-dir /path/to/dist` 可完全覆盖内置资源，保留原有目录、文件数量、
体积、符号链接及敏感文件检查。覆盖目录无效则启动失败，不回退内置页面；
未指定时不查找当前目录的前端文件。外部覆盖需重启生效，不支持热加载。

## 指标语义与范围

- 在线/离线会话、排队、inflight、订阅和保留消息读取已提交状态，跨会话视图
  为最终一致。持久数据恢复后可见；不创建额外持久化或读取未提交 SQLite 状态。
- 消息计数为入站收到/出站成功 flush 的 PUBLISH 帧数，包含重传；字节为编码
  MQTT 帧，排除 TCP/TLS/WS 开销。它们不是业务唯一消息数或事务成功数。
- 速率由页面两次成功采样的计数差与经过时间计算。进程重启清空历史；历史
  保存在当前页面内存，最多 60 个样本，不是长时监控系统。
- CPU/RSS、事件历史、会话管理变更尚未实现；页面标记不可用，不显示
  演示指标。没有证书身份映射，不推断客户端 IP/用户名。
- 不暴露消息 Payload、令牌、密码哈希、证书、私钥及配置文件路径。

精确接口与资源限额见 [Phase4f 契约](contracts/phase4f-dashboard.md)。

## 前端组件

React + Tailwind CSS v4 + shadcn/ui。布局使用工具类，按钮、卡片、输入框、
徽章、表格和原生选择框使用官方组件源码，图标使用 Lucide。只保留61行主题、
基础样式及原生 dialog 背景 CSS。组件来源与许可见
`dashboard/web/THIRD_PARTY_NOTICES.md`；详情面板使用原生 dialog，保持严格 CSP。

规则管理默认启用，配置保存到 SQLite；`--rules-config PATH` 可自定义数据库位置。详见 [SQL 与 Webhook](rules-webhook.md)。
支持 SQL 样例测试、出站配置（类型、目标和发送策略）和真实执行统计。规则接纳仍为 best-effort；
出站记录刷盘后由通用耐久队列恢复，不将 MQTT ACK 与出站落盘绑定。


规则和出站的内部标识在新建时自动生成，不再要求用户填写；列表、绑定和统计
以名称展示。现有配置的标识和引用保持不变，同名目标在绑定时显示地址帮助区分。
表单开关、勾选、文本域、标签页、标签和提示使用共享 UI 组件；MQTT Client ID
等协议字段仍正常展示与查询。


Webhook 表单默认只显示名称、地址和鉴权/请求头。批量、超时与重试参数位于默认
折叠的“高级设置”；不展开也能保存并使用默认策略。编辑已有出站会保留原策略。
队列容量不再提供编辑，新建由默认值管理，已有容量保持不变。

新建 Webhook 默认逐条发送（每批1条、等待0ms）；需要批量时在高级设置调整。
已有出站保存的策略不自动改写。

高级设置支持“并发请求数”（默认8，范围1–16）；同一规则、同一 Client 按顺序发送，
不同规则或 Client 并发，重试只阻塞当前规则的 Client，最终失败后继续下一条。执行状态增加进行中请求数，与排队、已发送的消息条数区分。

通用耐久出站队列启用后，“待完成投递”“待发送数据量”和出站待完成列显示
耐久积压，重启后按保存记录恢复；发送/失败等累计计数从本次进程开始。
有积压时修改出站目标或删除会被拒绝，禁用保留积压，重新启用继续发送。

规则结果共享后，“待完成投递”按各出站分别计数，待发送数据量按唯一结果正文
计一次；一个结果发送到两个出站，会显示两次待完成投递。当前页面不展示日志
文件、偏移或存储格式。
