# Phase3 local measurements — 2026-10-29

The18-run completion-gated baseline passed with exact counts. This is a bounded
local baseline, not maximum capacity, a production SLA or completion of all future
performance hardening. ACK-only hot stress also exposed incomplete/failed runs,
recorded separately below. No confirmed new production protocol defect was found;
measurement/fixture defects were fixed before this final profile.

stable, Python3.14.7; production edition2024, default Cargo release optimizations.
Broker and Python clients share loopback. Power/thermal state and unrelated system

ran during measurements. Each fresh broker uses SQLite WAL/synchronous FULL or
volatile memory as labeled. CleanStart1,SessionExpiry60,KeepAlive0,TopicAlias0,
256-byte payloads,QoS1 ingress/QoS0 subscription grants; bounds in raw broker argv.
Per publisher, both its PUBACK and every target receipt gate the next publication.

## Failed offered-load attempts and scope

The initial ACK-only attempt completed three memory/concurrent runs but failed on
a non-PUBACK during its first32-subscriber hot run. Its assertion did not retain
header/body; that original response remains unclassified. A same-configuration
ACK-only diagnostic with improved response capture reached its600s per-case limit
before completing a run; it did not reproduce that reply. Both incomplete datasets
and traces are preserved, not pooled into this passed completion-gated baseline.

An independent small-capacity1 ACK-only smoke (4 subscribers,2 producers,expiry60,
64 measured messages requested,8 warmup) received exact `0xe0 body=97 reason=0x97`:
legal Quota Exceeded. This proves that independent resource-rejection path, not the
cause of the original unknown reply. Correctness tests separately prove atomic
fanout rejection and preservation/recovery of already accepted durable work.
ACK-only stress does not have a successful full throughput figure in this evidence.

Source review found full-engine clones, repeated whole-registry serialization,
per-publication route rebuilds, broadcast-induced empty polls and whole SQLite
snapshot commits as profiling candidates. No profiler CPU percentages or runtime
speedup are claimed. Different flow policies cannot support an optimization claim.
Next: collect actor/empty-poll counts, clone/serialization CPU, snapshot bytes and
commit latency; capture partial failed-run metrics and investigate the unexplained
initial reply. Then freeze optimization contracts preserving ACK/expiry/recovery.
Longer soak, larger/multi-host clients, wildcard distributions, outbound QoS1/2 and
production resource/latency targets remain beyond this baseline.
